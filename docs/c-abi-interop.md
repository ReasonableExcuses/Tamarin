# Tamarin C ABI Interoperability Specification

**Version:** 0.18.5  
**Target:** C99 / POSIX / Win32 Calling Conventions  
**Classification:** Systems ABI & Foreign Function Interface (FFI)  

---

## 1. Overview and Design Philosophy

Tamarin provides native, zero-glue interoperability with standard C99 and C++ codebases. Code compiled with Tamarin can:
1. Directly call existing C APIs without wrapper libraries or marshalling overhead.
2. Export compiled Tamarin functions and structs to be consumed directly by C, C++, Rust, Python, or Go.
3. Automatically emit verified C99 header files (`--emit-header`).

---

## 2. Struct Layout Control: `@c_layout`

By default, Tamarin struct fields may be reordered by the compiler to minimize padding and optimize cache-line alignment. To enforce strict platform-standard C struct layouts, structs are annotated with `@c_layout`:

```tamarin
@c_layout
public struct Point3D {
    float x;
    float y;
    float z;
};
```

### 2.1 Alignment and Padding Guarantees
- Field offsets strictly match the host platform's C compiler (MSVC on Windows, GCC/Clang on Linux/macOS).
- Natural alignment is applied to all scalar members:
  - `i8`, `u8`: 1-byte alignment.
  - `i16`, `u16`: 2-byte alignment.
  - `i32`, `u32`, `float`: 4-byte alignment.
  - `i64`, `u64`, `double`, pointers: 8-byte alignment.
- Struct total size is padded to a multiple of the largest member's alignment.

## 3. Function Export and Header Emission

### 3.1 `@export` Modifier
Annotating a `public` function with `@export` instructs the compiler to:
1. Disable name mangling (equivalent to `extern "C"`).
2. Apply the platform's default C calling convention (`__cdecl` / System V AMD64 ABI).
3. Export the symbol in dynamic libraries (`__declspec(dllexport)` on Windows, `__attribute__((visibility("default")))` on POSIX).

```tamarin
@export
public int vector_dot_product(Point3D a, Point3D b) {
    return (int)(a.x * b.x + a.y * b.y + a.z * b.z);
}
```

### 3.2 Automated C Header Generation (`--emit-header`)
Running `tamarin` with `--emit-header` produces a standalone, self-contained C99 header file:
```bash
tamarin library.tmn -O3 --emit-header --shared -o library.dll
```

#### Generated Header Example (`library.h`):
```c
/* Generated by Tamarin Compiler v0.16.0 */
#ifndef TAMARIN_GENERATED_LIBRARY_H
#define TAMARIN_GENERATED_LIBRARY_H

#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

#if defined(_WIN32) || defined(__CYGWIN__)
  #if defined(TAMARIN_EXPORT_SYMBOLS)
    #define TAMARIN_API __declspec(dllexport)
  #else
    #define TAMARIN_API __declspec(dllimport)
  #endif
#else
  #define TAMARIN_API __attribute__((visibility("default")))
#endif

typedef struct Point3D {
    float x;
    float y;
    float z;
} Point3D;

TAMARIN_API int32_t vector_dot_product(Point3D a, Point3D b);

#ifdef __cplusplus
}
#endif

#endif /* TAMARIN_GENERATED_LIBRARY_H */
```

### 3.3 Decayed Array and String Pointer Returns
When an `@export` function or internal helper returns a decayed fixed-size array pointer or string slice (`char*`), the LLVM codegen backend tracks value pointer classifications (`isPointerValue_`), emitting valid `ret ptr` opcodes rather than illegal scalar bitwidth conversions. This guarantees seamless calling convention compliance with standard C pointers without runtime segmentation faults or compiler type assertions.

## 4. Complex Type Boundary Rules

When passing data across foreign function boundaries, strict semantic rules are enforced:

### 4.1 Capturing Closures
- Tamarin closures are represented in memory as a 16-byte fat structure:
  ```c
  typedef struct {
      void (*invoke)(void* ctx, /* arguments... */);
      void* ctx;
  } TamarinClosure;
  ```
- Because C does not possess a standardized fat-pointer closure type, Tamarin functions accepting or returning closures cannot be marked `@export` unless decomposed into an explicit function pointer and `void*` context parameter.

### 4.2 Asynchronous Tasks (`Task<T>`)
- A `Task<T>` across the C ABI is represented as an opaque handle `void*`.
- Standard C callers must interact with asynchronous tasks via runtime entry points:
  ```c
  TAMARIN_API void* tamarin_task_spawn(void* (*fn)(void*), void* arg);
  TAMARIN_API void* tamarin_task_await(void* task_handle);
  ```

### 4.3 Slices and Strings
- Slices `[]T` are lowered as 16-byte structs: `(T* data, uint64_t len)`.
- Strings in Tamarin are immutable UTF-8 slices `(const char* data, uint64_t len)`. For C functions requiring null-terminated strings (`const char*`), string literals implicitly decay to C-compatible pointer types.

### 4.4 Raw C FFI Pointers and String Literal Decay
Tamarin supports raw C pointers for seamless FFI:
- **Prefix Pointer Syntax**: Raw C pointers can be declared with prefix `*` (`*u8 ptr;`, `*const u8 cstr;`, `**int handle;`) as well as suffix `*` (`u8* ptr;`, `const u8* cstr;`).
- **Uninitialized Pointer Declarations**: Unlike safe `&T` references which must be bound immediately to an lvalue, raw C pointers `*T` can be declared uninitialized and assigned later (`ptr = &val;`). Definite assignment analysis ensures uninitialized pointers are not read before assignment.
- **String Literal Decay**: String literals implicitly decay to C-compatible pointer types (`*const u8`, `const u8*`, and `*u8` / `u8*` when interfacing with C functions such as `puts`), passing the underlying null-terminated byte buffer directly to C functions without manual conversion.
- **Pointer Arithmetic and Indexing**: Raw pointers support pointer arithmetic (`p + n`, `p - n`, `p2 - p1`) and direct subscript indexing (`p[i]`).

## 5. Linking Models

Tamarin supports both dynamic and fully static linking models:

### 5.1 Dynamic Linking (`--dynamic`, `--shared`)
- Compiles the source into a dynamically linked library (`.dll` on Windows, `.so` on Linux, `.dylib` on macOS).
- Links against the shared C runtime and shared `tamarin_runtime.dll`.

### 5.2 Static Native Executable (`--static`)
- Generates a standalone, dependency-free native executable.
- Statically embeds `tamarin_runtime_static` and the static C runtime (`/MT` on MSVC), producing a single binary deployable without external runtime dependencies.

## 6. Automated C Binding Generation (`tamarin-bindgen`)

`tamarin-bindgen` is an automated tool that parses C/C++ header files via `libclang` and emits idiomatic Tamarin bindings:

### 6.1 CLI Usage
```bash
# Standalone tool
tamarin-bindgen library.h -o bindings.tmn

# Integrated compiler subcommand
tamarin bindgen library.h -o bindings.tmn --clang-args="-I/usr/include"
```

### 6.2 Translation Rules

| C Declaration | Generated Tamarin Binding | Notes |
| :--- | :--- | :--- |
| `typedef struct { float x; float y; } Point;` | `@c_layout struct Point { float x; float y; };` | Preserves natural field alignments and padding |
| `void render(const Point* pt, int count);` | `extern "C" void render(*const Point pt, int count);` | C ABI `extern "C"` declaration |
| `enum Status { OK = 0, ERR = 1 };` | `enum Status { OK, ERR }` | Sequential C enums map to Tamarin ADT enums |
| `enum Flags { READ = 1, WRITE = 2 };` | `const int READ = 1; const int WRITE = 2;` | Bitflag/non-sequential enums map to constants |
| `#define MAX_BUFFER 4096` | `const int MAX_BUFFER = 4096;` | Preprocessor integer and float macros |
| `int arr[16];` | `int arr[16];` | Fixed-size arrays |
| `void (*callback)(int code);` | `*void callback; /* fn(int) -> void */` | Thin C function pointer callbacks |

### 6.3 Identifier Sanitization
Any C identifiers colliding with Tamarin reserved keywords (`type`, `trait`, `fn`, `match`, `auto`, `class`, `spawn`, `sync`) are automatically suffixed with an underscore (`type_`, `trait_`, `fn_`, `match_`).

## 7. GUI and Graphics Ecosystem Interop Strategy

Tamarin adopts an ecosystem-first strategy for graphics, windowing, and graphical user interfaces:
- **Zero Compiler Bloat**: GUI is not baked into the core compiler or standard library runtime. This maintains rapid compilation times, zero extra binary size for headless systems or server backends, and full embeddability.
- **First-Class C ABI Bindings**: Graphics libraries (such as **Raylib 5.5**, **SDL3 Platform**, and **Modern Multi-Backend `SDL_GPU`**) interoperate natively using `extern "C"` declarations and `@c_layout` struct definitions generated by `tamarin-bindgen`.
- **Package Distribution**: Graphics packages are distributed as modular `troop` packages with automated project scaffolding (`troop new -t raylib-game`, `troop new -t sdl3-app`) and automatic native `.dll` deployment on Windows.
- **Production Validation**: Evaluated in `benchmarks/projects/gui_test/` via a fully functional Raylib 5.5 GUI Calculator, proving identical performance (20.01 ms frame time, 502 KB binary) and total memory safety without `unsafe` blocks.
